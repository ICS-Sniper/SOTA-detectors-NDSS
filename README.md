# ICS Attack Detectors against ICS-Sniper

This artifact evaluates network-based and process log-based intrusion detectors against attacks generated by ICS-Sniper. It contains preprocessed IPAL datasets, detector configurations, experiment notebooks, evaluation utilities, and a single-notebook quick start that reproduces the train, validation, attack-detection, and plotting workflow.

The implementation builds on the [IPAL IIDS Framework](https://github.com/fkie-cad/ipal_ids_framework) and its ensemble strategies. The InvariantRules and PASAD implementations are not part of the public upstream IPAL release and are therefore not included in this repository. Their configurations remain in the artifact, but running them requires obtaining the implementations from the IPAL authors and placing them under `ipal_ids_framework/ids/invariant_rules/` and `ipal_ids_framework/ids/pasad/`, respectively.

## Quick start

### 1. Set up the environment

Clone the repository and enter its root directory, then create the development environment:

```bash
./setup_development_venv.sh
source ./activate_ipal.sh
```

The setup script creates an ignored `ipal-dev/` virtual environment.

### 2. Run a minimal public example

Before running the complete notebook workflow, verify the environment with a single public process detector. From the repository root, this S3 MinMax example uses the same training data, attack input, ground truth, and detector configuration as `quick_start.ipynb`:

```bash
ipal-iids --retrain \
    --config config/quick_start/S3/minmax.config \
    --train.state dataset/20260411-clean/full_training.state.gz \
    --live.state dataset/scenario-3-attack/S3_att.state.gz \
    --output output.state.gz

ipal-evaluate \
    output.state.gz \
    --attacks dataset/scenario-3-attack/1_attacks.json \
    --output output.json

ipal-plot-alerts \
    output.state.gz \
    --attacks dataset/scenario-3-attack/1_attacks.json \
    --output S3-minmax-alerts.png
```

This example does not require the non-public InvariantRules or PASAD implementations. A successful run creates `output.state.gz`, `output.json`, and `S3-minmax-alerts.png` in the repository root.

### 3. Run the notebook workflow

Start Jupyter from the repository root:

```bash
jupyter notebook quick_start.ipynb
```

In `quick_start.ipynb`, set `SCENARIO` to a value from 1 to 5 and run the cells from top to bottom. The notebook checks the selected inputs, validates the detectors on benign data, retrains and runs them on the selected attack, evaluates their outputs, and creates separate network detector and process detector alert plots.

By default, the notebook includes InvariantRules, PASAD, and process-detector Any/All ensembles that depend on both implementations. Without the non-public implementations, execution stops when InvariantRules is loaded and the complete process-detector workflow and plots cannot be produced. To run only the publicly available process detectors, add the following line immediately after the `STATE_JOBS` definition:

```python
STATE_JOBS = STATE_JOBS[:3]
```

This public subset runs Histogram, MinMax, and SteadyTime while omitting InvariantRules, PASAD, and the dependent process-detector Any/All ensembles. The network-detector jobs are unaffected. Full reproduction of all process-detector results requires the non-public implementations.

All benign training data, attack inputs, and attack ground truth required by the five scenarios are included under `dataset/`.

## Optional raw-data transcription

Users who want to reproduce the preprocessing step can run `dataset/transciber.ipynb`. The notebook uses the raw `dataset/transcriber/S3_att.csv` and `dataset/transcriber/S3_att.pcap` files as examples and generates `S3_att.state.gz` and `S3_att.ipal.gz`, respectively.

The notebook demonstrates four separate steps:

1. Normalize the CSV columns and transcribe the process log to IPAL state records.
2. Transcribe the Modbus PCAP with `ipal-transcriber` and the included `dataset/transcriber/rules-modbus.py` rules file that is only applicable to the ICS-Sniper hardware testbed.
3. Run `_ensure_ipal_timestamp_order` to detect and correct out-of-order network records.
4. Run `ipal-add-attacks` to annotate the generated datasets with attack intervals.

## Scenarios

| Scenario | Attack and testbed |
| --- | --- |
| S1 | Process delay attack on S-EN-BASE |
| S2 | UF-Depletion attack on S-EN-BASE |
| S3 | Process delay attack on H-MD-BASE |
| S4 | Process delay attack on H-MD-LOSS |
| S5 | Process delay attack on H-MD-LOSS-EXT |

The quick start resolves the benign training and attack inputs as follows:

| Scenario | Benign training directory | Attack input directory | Configuration family |
| --- | --- | --- | --- |
| S1 | `dataset/20251111/` | `dataset/scenario-1-attack/` | `tuned_enip` |
| S2 | `dataset/20251111/` | `dataset/scenario-2-attack/` | `tuned_enip` |
| S3 | `dataset/20260411-clean/` | `dataset/scenario-3-attack/` | `base` |
| S4 | `dataset/20260411/` | `dataset/scenario-4-attack/` | `tuned` |
| S5 | `dataset/20260504/` | `dataset/scenario-5-attack/` | `tuned` |

Scenario directory numbers match the S-numbers used in plot names and paper results.

## What the quick start runs

Network detectors:

- InterArrivalTimeMean
- InterArrivalTimeRange
- Kitsune
- Any and All ensembles

Process detectors:

- Histogram
- MinMax
- SteadyTime
- InvariantRules
- PASAD
- Any and All ensembles

Validation artifacts are written to `utils/scenario-<S>-attack/quick_start_result/validation/`. Attack outputs, evaluation JSON files, logs, and the final `S<S>-networkDetectors.png` and `S<S>-stateDetectors.png` figures are written to `utils/scenario-<S>-attack/quick_start_result/`.

## Repository layout

- `quick_start.ipynb`: recommended entry point for one complete scenario.
- `dataset/<date>/`: benign message and process-state training data used by the five scenarios.
- `dataset/scenario-<S>-attack/`: attack ground truth and preprocessed message/state attack inputs for S1-S5.
- `dataset/transciber.ipynb`: optional CSV/PCAP transcription, timestamp-order correction, and attack-labeling workflow.
- `dataset/transcriber/`: raw S3 transcription examples and the Modbus rules file.
- `config/`: baseline detector configurations.
- `config/quick_start/S<S>/`: self-contained detector and ensemble configurations selected for each scenario.
- `utils/scenario-<S>-attack/`: detector configurations, original experiment outputs, and isolated quick-start results.
- `ipal_ids_framework/`: detector implementations.
- `ipal_evaluate/`: evaluation and plotting tools.

The `utils/` directory is intentionally excluded from this release branch. `quick_start.ipynb` creates all required runtime directories automatically.
